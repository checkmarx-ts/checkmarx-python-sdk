## 4. Key Takeaways

1. **DAST is the largest real gap by far**: `DAST_SCANS_MANAGER.yaml` (89 missing) and `DAST_RESULTS.yaml` (41 missing) together account for 58% of all missing endpoints. `dastScanAPI.py`/`dastResultsAPI.py` cover only a slice of what's now documented for these services.
2. **`POLICY_MANAGER.yaml` (27, entirely unwrapped)** is the next-largest genuine gap, followed by `INTEGRATIONS_REPOS.yaml` (10), `AI_AGENTS_COORDINATOR.yaml` (7), and `KICS_POLICY_ENGINE.yaml`/`SAST_POLICY_ENGINE.yaml` (6 each).
3. **41 deprecated endpoints** remain Python-only with no YAML match on this feed. Two whole services -- `healthCheckServiceAPI.py`'s `/api/healthcheck/*` and `repoManagerAPI.py`'s `/api/repos-manager/scms/*` family -- have no corresponding spec on this feed at all and are worth a manual check against the running product to confirm they still work.
4. **This refresh roughly doubled measured coverage on paper** (214→385 matched, 270→427 Python endpoints) mostly because the SDK itself grew substantially since this doc was last generated (new `riskOrchestrationAPI.py`, `scaManagementOfRiskAPI.py`, `scaPrivateRegistryConfigAPI.py`, etc.), and because several previously-"deprecated" DAST endpoints now have matching specs once `DAST_RESULTS.yaml`/`DAST_SCANS_MANAGER.yaml` were pulled in.
5. **`SCA_MANAGEMENT_OF_RISK.yaml`/`SCA_PRIVATE_REGISTRY_CONFIG.yaml`** backing `scaManagementOfRiskAPI.py`/`scaPrivateRegistryConfigAPI.py` are not present on this spec feed at all, so those two modules can't be cross-checked this way.
